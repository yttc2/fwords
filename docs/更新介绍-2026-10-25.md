# 版本更新 · 2026-10-25

> 本次更新只做一件事：**修手机端回顾被打断就回不来的问题**，不涉及新功能，不改变背单词的主流程。
> 已有进度、词库、存档全部兼容，不用清数据。

---

## 一句话

手机上背到一半触发回顾，切个后台回来，人就被扔回首页、那次回顾白做了 —— 现在会**回到原来那一个词**接着看。

## 问题是怎么发生的

回顾页的「这次回顾有哪些词、看到第几个」原来只放在内存里，不进存档。

手机浏览器（微信内置浏览器、iOS Safari）在内存吃紧时会把整个页面回收掉，切回来其实是**重新打开一次**。重新打开时只看到存档里记了一个「回顾类型」，没有进度、也没有词表，程序只能按最保守的做法处理：把这次回顾作废，回首页，再提示一句「上次的回顾被中断，已跳过」。

所以只有部分情况会撞上（页面真被回收才会），但一旦撞上就是白做一遍。**30 分钟回顾最容易撞**：它词最多、停留时间最长、被回收的概率也最高。

## 这次改了什么

| | 以前 | 现在 |
|---|---|---|
| 切后台 / 锁屏 / 按返回键回来 | 掉回首页，回顾作废 | **回到原来那个词**，顶部提示「已回到上次的回顾：30 分钟回顾　第 4 个」 |
| 进度 | 不记录 | 看到第几个就回到第几个 |
| 回顾类型 | 只记 T1/T2/T3 | 三种都支持，30 分钟回顾同样恢复 |
| 老存档 | — | 直接读，当成「从第 1 个继续」，不用清数据 |

两种情况仍然不会拦人：

- 在设置里**关掉「回顾机制」**之后重新打开，旧的未完成回顾会静默作废，不会把人拽回回顾页。
- 回顾的词表已经失效（比如中途换过词库），提示「上次的回顾词表已失效，已跳过」，然后正常回首页。

## 需要知道的一个变化

> **重新打开页面 = 接着做完，不再是跳过。**

以前「关掉再打开」实际上是个绕过回顾的后门，这次把后门堵上了。回顾本来就没有「跳过」按钮，被打断的 30 分钟回顾需要看完剩下的词才能继续学。如果确实需要一个「稍后再看」的出口，可以再提。

## 技术要点（答辩 / 评审用）

回顾期间计时是停的，`learnedLog` 也不变，所以按类型重算回顾词表的函数是**幂等**的 —— 同一个类型每次算出来的词表完全相同。因此不需要把整份词表塞进存档（存档是每秒写一次的，塞进去会明显变重），**只记「类型 + 看到第几个」就够**：

- `state.activeReview`：由 `'T3'` 升级为 `{ type: 'T3', idx: 3 }`，旧存档的裸字符串由 `normalizeActiveReview()` 归一化（向前兼容）。
- `startReview(type, fromIdx)` 支持从断点进入；新增 `syncReviewCursor()`，前进 / 后退都把位置写回状态。
- 启动时能重建就直接回到回顾页第 `idx` 个词（不经过触发判定，否则会从 0 重来）；词表为空或越界才结算跳过。
