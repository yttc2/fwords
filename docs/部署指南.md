# Fwords Web Demo · 部署指南

> 你的环境：**Linux 服务器 + 宝塔面板 + 已备案/未备案域名**
> 两个包，按用途选（**zip 内都是扁平结构，解压到站点根目录即用**）：
> - `dist/fwords-demo-clean.zip`（203 KB）—— **上线公网用这个**，不含导入的私有词库
> - `dist/fwords-demo.zip`（290 KB）—— 本地 / 内网自用，含导入的全部词库
>
> 要不要用子域名？直接跳 **第 3 节**。

---

## 0. 先说清楚这东西是什么

Fwords Web Demo 是**纯静态站点** —— 11 个文件，没有后端、没有数据库、没有构建步骤、没有任何依赖。

| 文件 | 作用 |
|---|---|
| `index.html` | 页面结构（六个视图：首页 / 词库 / 学习 / 回顾 / 结果 / 调试） |
| `style.css` | 样式 |
| `fw-core.js` | core 层：常量、本地存储、状态容器、通用工具 |
| `fw-model.js` | model 层：词表解析与分组、词库注册表、持久化、回顾调度 |
| `fw-speech.js` | speech 层：发音（在线真人音源为主，系统 TTS 兜底） |
| `fw-view.js` | view 层：全部渲染与视图切换 |
| `fw-controller.js` | controller 层：事件绑定、手势、流程推进、计时循环 |
| `app.js` | 引导：组装各层并启动（很小，2.9 KB） |
| `wordlists.js` | 内置考研词库 5047 词 + 「十天计划」形态（393 KB，包体积主要在这里） |
| `wordlists.user.js` | 你自己导入的词库（当前是《十天搞定考研词汇》2881 词，227 KB） |
| `words.js` | 示例词库（CET-4 高频 120 词，用于快速试跑） |

> **6 个脚本的顺序不能改**（`fw-core → fw-model → fw-speech → fw-view → fw-controller → app`）：
> 每层在加载时按顺序抓取上游层，顺序错了会直接报错。zip 里已经排好，别手工调整。

所以**不需要装 Node、Java、Docker，也不用建数据库**。宝塔添加站点时 PHP 选「纯静态」就行。

> **一个关于内容的提醒（重要）**：`wordlists.user.js` 装的是你导入的词库。当前导入的是**正版商业出版物《十天搞定考研词汇》**的完整内容 —— 释义、音标、编排都受版权保护。把它放上公网等于**向公众分发**，性质和本地自用不同。
>
> 约定：这类词库**只在本地用**。上线时请改用精简包：
>
> ```bash
> python tools/pack.py --clean    # 把 wordlists.user.js 换成空壳，只留开源词库
> ```
>
> 内置的 `wordlists.js`（开源考研词库 5047 词）可以正常发布。注意：静态 JS 只要传上去任何人都能下载，**加密码也拦不住有访问权的人** —— 所以真正的做法是线上不放，而不是藏起来。

## 1. 三个必踩的坑（先说在前）

**坑 1：不能双击 `index.html` 测。**
`file://` 协议下浏览器行为不一致，手机上打不开本地文件。必须走 HTTP 服务。

**坑 2：端口要放行两层。**
宝塔的「安全」页面是一层，**云控制台的安全组是另一层**。只开一层 = 访问不通。这是第一次部署最常卡住的地方。

**坑 3：微信里可能没声音。**
Demo 的发音走浏览器原生 `speechSynthesis`，微信内置浏览器（X5 内核）对它支持很差，很可能点了不出声。**测试请用系统自带浏览器**（iOS Safari / Android Chrome）。这不是部署问题，是内核限制。

**坑 4（国内服务器专有）：域名要备案。**
如果服务器在阿里云/腾讯云等**国内**厂商，域名必须完成 ICP 备案，否则走 80/443 访问会被拦截。备案一般 1–2 周。**还没备案的话，先用 IP 访问测试**，功能完全一样，只是没有 HTTPS。

## 2. 【你的情况】宝塔面板 + 域名 · 完整步骤

### 步骤 1：域名解析

去你的域名服务商（腾讯云 DNSPod / 阿里云云解析等）添加两条 A 记录：

| 主机记录 | 记录类型 | 记录值 |
|---|---|---|
| `@` | A | 你的服务器公网 IP |
| `www` | A | 你的服务器公网 IP |

验证是否生效（本地终端里跑）：

```bash
nslookup 你的域名
# 或者
ping 你的域名
```

返回的 IP 是你的服务器 IP，就说明解析生效了（刚加的记录可能要等几分钟到几小时）。

### 步骤 2：宝塔添加站点

1. 面板左侧 **网站 → 添加站点**
2. **域名**：填 `example.com`（换成你的域名），回车后再填 `www.example.com`，一行一个
3. **根目录**：默认 `/www/wwwroot/example.com`，不用改
4. **FTP**：不创建 &nbsp;·&nbsp; **数据库**：不创建 &nbsp;·&nbsp; **PHP 版本**：选 **纯静态**
5. 提交

> 提交后宝塔会自动在根目录生成 `index.html`、`404.html`、`.user.ini`。其中 `index.html` 是宝塔的默认占位页，下一步会被我们的文件覆盖掉，这是正常的。

### 步骤 3：上传并解压

1. 面板左侧 **文件** → 进入 `/www/wwwroot/example.com`
2. 点 **上传**，选 `dist/fwords-demo.zip`，等上传完
3. 右键刚上传的 zip → **解压** → 解压到**当前目录**
4. 因为 zip 内是扁平结构，解压后根目录应**直接**出现这 11 个文件：
   ```
   /www/wwwroot/example.com/
     ├─ index.html          ← 已被我们的文件覆盖
     ├─ style.css
     ├─ fw-core.js          ┐
     ├─ fw-model.js         │
     ├─ fw-speech.js        ├─ MVC 分层，顺序不能改
     ├─ fw-view.js          │
     ├─ fw-controller.js    │
     ├─ app.js              ┘  ← 引导
     ├─ words.js
     ├─ wordlists.js        ← 开源考研词库，393 KB，别漏了
     └─ wordlists.user.js   ← 导入的词库：完整包 227 KB / 精简包只剩空壳
   ```
   如果解压出来是一个 `fwords-demo` 文件夹，说明传的是旧包 —— 把里面的文件剪切到根目录即可。

> ⚠️ 根目录里必须**直接**能看到 `index.html`，多套一层文件夹是 404 的头号原因。
> ⚠️ **不要**去改站点设置里的「运行目录」—— 扁平包不需要。

### 步骤 4：放行端口

1. **宝塔**：左侧 **安全** → 放行 `80`（HTTPS 还要放行 `443`）
2. **云控制台**：找到你这台服务器的**安全组** → 入方向规则 → 添加 `80/tcp` 和 `443/tcp`

两层都要放行。

### 步骤 5：验证访问

在服务器本机先测一下，能分清是「服务没起来」还是「网络不通」：

```bash
curl -I http://127.0.0.1
curl -I -H "Host: 你的域名" http://127.0.0.1
```

返回 `200 OK` 说明站点本身没问题。然后用手机浏览器打开 `http://你的域名`，应该直接看到背单词首页。

### 步骤 6：申请 SSL 证书（域名已备案的话）

1. 网站列表 → 点站点名 → 进站点设置 → **SSL**
2. 选 **Let's Encrypt** → 勾选你的两个域名 → 验证方式选 **文件验证** → 申请
3. 签发成功后，打开 **强制 HTTPS** 开关

**为什么值得开 HTTPS：**
- 微信里能正常打开（HTTP + 域名在国内也可能被拦）
- 手机上可以「添加到主屏幕」，全屏运行，接近原生 App 的体验
- iOS Safari 下 `speechSynthesis` 的可用性更稳

> 申请 Let's Encrypt **需要域名已解析到本机并且 80 端口可访问**。如果申请失败，先回头确认步骤 1 和步骤 4。

### 步骤 7：真机验证（这一步才是重点）

用**系统自带浏览器**打开你的域名，重点验证三件事：

1. **发音** —— 点卡片上的小喇叭，听是否有声音、音色是否可接受
2. **滑动** —— 左滑下一个、右滑上一个，手感是否顺畅
3. **断点续背** —— 背几个词后杀掉浏览器重开，看进度是否恢复

这三样是我在 Node 里模拟不了、必须真机确认的。

## 3. 用子域名部署（主域名已经在用）

主域名已经占了一个站点，想再挂一个子域名（比如 `fwords.example.com`）给 Fwords —— **不用买新服务器，也不用动原站点**。

**原理**：宝塔的 Nginx 是**按请求的域名（Host 头）**把请求分发到不同站点的。子域名只要解析到同一台机器，Nginx 就会把它交给对应站点，原站点完全不受影响。

```
浏览器访问 fwords.example.com
   ↓ DNS 解析
你的服务器 IP
   ↓ Nginx 看 Host 头分发
   ├─ example.com        → 原站点（不动）
   └─ fwords.example.com → 新站点（Fwords）
```

### 步骤 1：加一条 DNS 解析

去域名服务商控制台（腾讯云 DNSPod / 阿里云云解析）添加：

| 主机记录 | 记录类型 | 记录值 |
|---|---|---|
| `fwords` | A | 你的服务器公网 IP |

验证是否生效：

```bash
nslookup fwords.example.com
```

返回你的服务器 IP 就对了。**这一步没生效，后面全白忙。**

### 步骤 2：宝塔添加站点

1. 面板左侧 **网站 → 添加站点**
2. **域名**：`fwords.example.com`
3. **根目录**：默认 `/www/wwwroot/fwords.example.com`，不用改
4. **FTP / 数据库**：都不创建 &nbsp;·&nbsp; **PHP 版本**：选 **纯静态**
5. 提交

> 解析还没生效时，宝塔可能提示「域名未解析到本机」。可以先建、后生效，不影响。

### 步骤 3：上传哪个包？（这一步跟主站不一样）

| 传哪个 | 什么时候用 | 体积 |
|---|---|---|
| `dist/fwords-demo-clean.zip` | **上线到公网 → 推荐这个** | 203 KB |
| `dist/fwords-demo.zip` | 只在本地 / 内网自用 | 290 KB |

**为什么有区别**：`wordlists.user.js` 里装的是你导入的词库。书版《十天搞定考研词汇》是**正版商业出版物**，它的释义、例句、编排都受版权保护 —— 明文放上公网，性质和本地自用完全不同。

- **完整包**会把 227 KB 的书版词库原样带上线；
- **精简包**把它换成一个空壳（0.2 KB），线上只保留开源的考研词库。

后者不是「藏起来」的意思 —— 静态 JS 谁都下载得到，密码也拦不住有访问权的人。**真正干净的做法就是线上不放**。

```bash
python tools/pack.py --clean     # 线上精简包（剔除私有词库）
python tools/pack.py             # 完整包（本地自用）
```

两个包会同时留在 `dist/`，不会互相覆盖。

### 步骤 4：上传并解压

1. **文件** → 进 `/www/wwwroot/fwords.example.com`
2. 上传 `dist/fwords-demo-clean.zip` → 右键 → **解压到当前目录**
3. 确认根目录**直接**能看到 `index.html`（多套一层文件夹 = 404）

### 步骤 5：申请 SSL

站点设置 → **SSL** → **Let's Encrypt** → 勾选 `fwords.example.com` → 文件验证 → 申请 → 打开**强制 HTTPS**。

> ⚠️ 主域名的证书**不会自动覆盖子域名**。要么给子域名单独签一张，要么用泛域名证书（`*.example.com`，需要 DNS 验证）。

### 步骤 6：备案

主域名备案后，子域名一般可沿用（同一主体、同一接入商）。但**部分省份 / 服务商要求子域名单独做「接入备案」**，去备案后台确认一下，否则 80/443 可能被拦。

### 步骤 7（可选）：加密码访问

想只给自己看，加一层密码最省事：

站点设置 → **访问限制** → 开启**密码访问** → 填用户名密码 → 保存。

浏览器会弹系统登录框（HTTP Basic Auth），配合 HTTPS 就够用了。

> 提醒：Basic Auth 只挡入口、不加密内容。任何拿到密码的人都能下载全部文件 —— 所以**书版词库该不放还是不放**（见步骤 3）。

## 4. 方式 B：纯命令行 Nginx（不用面板时）

```bash
# 本地（Windows Git Bash，scp 系统自带）
scp D:/Fwords/dist/fwords-demo.zip root@你的服务器IP:/tmp/

# 服务器上
apt install -y nginx unzip          # CentOS 用 yum install -y nginx unzip
mkdir -p /var/www/fwords
unzip -o /tmp/fwords-demo.zip -d /var/www/fwords
ls -l /var/www/fwords/              # 确认 6 个文件直接在目录里

cat > /etc/nginx/conf.d/fwords.conf <<'EOF'
server {
    listen 80;
    server_name 你的域名 www.你的域名;
    root /var/www/fwords;
    index index.html;
    location / { try_files $uri $uri/ /index.html; }
}
EOF

rm -f /etc/nginx/sites-enabled/default      # Debian/Ubuntu 默认站点抢占 80，挪走
nginx -t && systemctl enable --now nginx && systemctl reload nginx
```

放行防火墙：

```bash
ufw allow 80/tcp && ufw allow 443/tcp                      # Ubuntu
firewall-cmd --permanent --add-service=http --add-service=https && firewall-cmd --reload   # CentOS
```

## 6. 改了代码后怎么重新上线

改了 `demo/` 下的代码后，本地按顺序跑：

```bash
python tools/pack.py --clean           # 线上用了精简包就跑这个
python tests/serve-check.py dist/fwords-demo-clean
# 或者本地自用的完整包：
python tools/pack.py
python tests/serve-check.py
```

自检会起一个本地 HTTP 服务，校验资源是否都能访问、引用是否都能解析。

自检通过后，把对应的 zip 重新上传到站点根目录、解压覆盖即可。

**改完看不到更新？** 静态资源被手机缓存了，按顺序试：

1. 手机浏览器强制刷新 / 用无痕窗口打开
2. 宝塔站点设置 → 配置文件里给静态资源设置较短缓存时间
3. 治本办法：给资源加版本号 `<link rel="stylesheet" href="style.css?v=2">`，改一次升一次号（要加我可以顺手改）

## 7. 访问不通？按这个顺序排查

| 现象 | 大概率原因 | 怎么查 |
|---|---|---|
| 完全连不上、超时 | 安全组/防火墙没放行 | 宝塔「安全」+ 云控制台安全组，都要放行 80 |
| 有响应但 403 | 目录权限或根目录路径不对 | `ls -l /www/wwwroot/你的域名/`，确认有 `index.html` |
| 有响应但 404 | 根目录多套了一层文件夹 | 根目录必须**直接**看到 `index.html` |
| 出现宝塔默认页 | `index.html` 没被覆盖 | 确认解压时覆盖了根目录的 `index.html`，或删掉它重新解压 |
| 域名打不开、IP 能打开 | DNS 未生效或未备案 | `nslookup 你的域名`；国内服务器还要看备案状态 |
| 页面出来了但没声音 | 微信内核不支持 TTS | 换系统浏览器（Safari / Chrome）试 |
| HTTPS 申请失败 | 80 端口不通或域名没解析 | 先确认步骤 1、步骤 4 |
| 改了代码打开还是旧的 | 浏览器缓存 | 无痕窗口验证 |

排查时最有用的一条命令：

```bash
curl -I http://127.0.0.1
```

本机通、手机不通 → 网络 / 防火墙 / DNS 问题。
本机就不通 → 文件路径或 Nginx 配置问题。

## 8. 前置检查：本机能跑通再上传

上传前建议先跑一次自检，排除「文件本身有问题」：

```bash
python tests/serve-check.py                          # 完整包
python tests/serve-check.py dist/fwords-demo-clean   # 精简包
```

它会临时起一个本地 HTTP 服务，检查 4 个资源是否都返回 200、首页引用是否都能解析。全绿再上传，出问题时就能确定是服务器环境的事。
