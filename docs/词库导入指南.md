# 词库导入指南

这份文档回答一件事：**怎么把「十天搞定考研词汇」（或你自己的电子词表）弄进 Fwords。**

---

## 0. 先说清楚王江涛那本书的情况

你要的是《十天搞定考研词汇》的原词。有几件事必须先摆出来，否则后面会走弯路。

**这本书的结构**（第 3 版，2024，浙江教育出版社）：

| 项 | 情况 |
|---|---|
| 单元 | **20 个 List，分 10 天**，每天 2 个 List（Day 1 = List 1-2，Day 2 = List 3-4 …… Day 10 = List 19-20） |
| 考频分级 | 五星词汇 List 1-2 / 四星词汇 List 3-6 / 三星词汇 List 7-20 |
| 词量 | 约 4600 词 |
| 每个词条的内容 | 音标、中文释义、记忆方法、真题例句、考点搭配、派生词 |

**没有合法的公开数据源。** 这本书是正版商业出版物，词表只能从纸质书或正版电子书里来，网上那些「txt / epub 下载」站点的东西不在我们考虑的范围内。

> **当前状态：已用正版电子版（MOBI）落地。** 老板提供了该书电子版，抽出 **2881 词**，音标与释义 **100% 覆盖**，20 个 List 原样保留、折成 10 天。做法见**路径 C → 电子书排版（.mobi）**。下文的路径 A / B 保留作备选方案。

**哪些部分受保护，哪些不受：** 单词本身来自考研大纲，是公开的；**受保护的是作者写的释义、真题例句、记忆方法、考点搭配，以及整本书的编排呈现**。

> 这直接给出一条更省事的路 —— 见下面的**路径 B**：你只需要提供「哪个词在哪个 List / 第几天」这个**顺序**，音标和释义由内置的开源考研词库按拼写配对补上。实测覆盖率 **100%**。这样你拿到的是「书的进度结构 + 合法来源的释义」。

**部署提醒（这条请认真看）：** 这个 Demo 现在挂在公网域名上。把自己的电子书内容整份放进去，等于**向公众分发**，性质和个人本地自用完全不同。建议二选一：
- 书版词库**只在本地用**（不上传到服务器），线上继续用内置的开源考研词库；
- 或者给站点加一层访问限制（宝塔的「访问限制」→ 开启密码访问）。

## 1. 三条路，怎么选

| 你的情况 | 走哪条路 | 要不要重新部署 |
|---|---|---|
| 只想按十天节奏背考研词，不要求跟纸质书逐词一致 | **路径 A：内置「十天计划」** | 不用 |
| 有书的词表顺序（哪怕是手打的一部分），要跟书一致 | **路径 B：词序 + 自动配对释义**（推荐） | 要 |
| 有完整的电子资源文件（xlsx / docx / txt / csv / ppt / **mobi**） | **路径 C：直接导入文件** | 要 |
| 只有几千词以内的小词表，想马上试 | **路径 D：网页端导入** | 不用 |

路径 B 和 C 都靠同一个工具 `tools/import_words.py`，区别只是「你喂给它多少信息」。

## 路径 A：内置的「十天计划」（最快，但不是那本书）

打开 Demo → 左上角「词库」。下拉**默认已选中「考研词汇 · 十天计划」**，点「载入全部」，首页就是 10 个格子（Day 1 ~ Day 10，每天 505 / 504 词）。

它是**开源考研词库 5047 词按 10 天等分** —— 词是考研词、结构是十天结构，但**词序和王江涛的书不一致**。只想按十天节奏背，这条路够用；要跟书完全对齐，走路径 B 或 C。

> 两个入口的区别（都指向同一份 5047 词）：
>
> | 入口 | 进内存方式 | 存档体积 | 适合 |
> |---|---|---|---|
> | 考研词汇 · 十天计划（默认） | 一次载入全部 | 约 446 K 字符 | 按十天整体推进，随时跳任意一天 |
> | 考研词汇 | 按批，默认每次 60 词 | 约 5 K 字符 | 低端机 / 每天只背一小批 |
>
> 446 K 字符约占 localStorage 配额的 9%。低端机觉得卡就切分批模式，体积降到 1/83。

## 路径 B：只给「词的顺序」，释义自动配对（推荐）

**适合：你手上有书的词表顺序，但不方便把整本书的内容搬进来。**

### 你只需要准备这样的文件

```
List 1
abandon
abstract
academic
accelerate
access
accommodate
List 2
acquire
adapt
adequate
adjacent
```

**每行一个单词**，前面加一行 `List 1` / `List 2` … 标出单元边界。音标和释义**不用写**。

### 一条命令

```bash
python tools/import_words.py "书的词表.txt" --name "十天搞定考研词汇"
```

工具会做两件事：

1. **补全**音标与释义 —— 从内置的开源考研词库按拼写配对（实测命中率 100%）
2. **折叠**成 10 天 —— `List 1` ~ `List 20` 每 2 个合一天，首页直接显示 `Day 1 (List 1-2)` … `Day 10 (List 19-20)`

输出示例：

```
词条            4600 个
音标覆盖        4600/4600（100%），本次补入 4600 个
释义覆盖        4600/4600（100%），本次补入 4600 个
分节折叠        20 个「List」→ 10 天（每 2 个一节合一天）
分节            10 节：Day 1 (List 1-2)(460)、Day 2 (List 3-4)(460)…
```

> **补全的边界**：词库里查不到的词**留空**，不会凭空编造 —— 编一个错的音标比空着更糟。报告里会如实写明补了多少、还剩多少没覆盖。

**这个文件的来源**：书最后的**正序索引**里有全部单词，抄一遍就是完整的词表顺序；或者对着目录把每页的单词敲进去一部分也行，工具按词数分节、支持增量补齐。

## 路径 C：直接把电子资源文件喂进去

支持 **xlsx / docx / csv / tsv / txt / md / json / ppt / pptx** —— 书版自然排版和课件排版都认。

```bash
python tools/import_words.py "十天搞定考研词汇.xlsx" --name "十天搞定考研词汇"
```

### 书版自然排版（txt / docx 正文）

一个词条跨多行、夹着考点和例句的排法：

```
abandon /əˈbændən/ vt. 抛弃，放弃；遗弃
【考点搭配】abandon oneself to 沉溺于
【例句】He abandoned his wife and children.
account
n. 账户；描述
```

工具按这套规则解析：

| 规则 | 说明 |
|---|---|
| 单词只取行首 | `abandon /əˈbændən/ vt. 抛弃` → 单词是 `abandon`，不是整行 |
| 音标从行尾抠 `/…/` | 支持 `/…/`、`[…]`、裸音标 token |
| `【…】` 标注行**整行丢弃** | 考点搭配 / 例句 / 记忆法 / 派生 —— 这些是书里版权最重的部分，App 也用不上（渲染和回顾只要单词 + 音标 + 释义） |
| 释义续行接回上一条 | `n. 账户；描述` 会接到 `account` 后面，而不是变成一个新单词 |
| 词性行不是词条 | `vt. 加速，促进` 不会被当成单词 |
| 多词级释义合并 | 同一个词出现多次，释义合并成一条 |

跑完会打印**跳过了多少行**，方便你核对没把有用内容当垃圾扔掉。

### 讲稿排版（.ppt / .pptx）

课件（比如那套「正课」讲义）是**一页一页往上加内容**的讲稿，和纸书排版完全不同：

```
1、intellect ['intəlekt](n.)智力，理解力；(总称)知识分子
哈工大航天学院38岁教授高会军
●intellectual [,intəl'ektʃuəl]（adj.）智力的；理智的，聪明的
考点搭配：intellectual enquiry 知识探索（2003年-翻译）
lect-表示“选择；收集”
【2015-1-1、2014-1-1】
```

同一页里混着词条、花絮、词根、考频标注、真题出处。所以 .ppt 走的是**先提取、再清洗**两段：

| 阶段 | 做什么 |
|---|---|
| 提取（`tools/ppt_extract.py`） | 旧版 `.ppt` 是 OLE2 复合文档（不是 zip），纯标准库按公开规范解析出每一页的文字。**不需要装任何东西**，也不依赖 PowerPoint / WPS |
| 清洗 | 剥掉行首序号（`1、` `1）` `●` `*`）、丢考点搭配/译文/词根行/真题出处/母版占位符、抠掉纯中文花絮，再把「单词和音标黏在一起」（`claimant['kleɪmənt]`）分开 |

清洗完再交给同一套书版解析规则，所以词条识别是一致的。

```bash
# 单个文件
python tools/import_words.py "正课(1).ppt" --name "王江涛正课1"

# 多个文件：每个文件自动成为一节
python tools/import_words.py "正课(1).ppt" "正课(2).ppt" ... --name "王江涛正课"

# 一个目录里全是课件：按文件名自然序排（正课(2) 排在 正课(10) 前面）
python tools/import_words.py --dir D:/ppt/正课 --name "王江涛正课"
```

**默认「一个文件 = 一节」**。十个正课文件就正好十节，App 首页就是 Day 1~Day 10。想按讲稿每一页分节，加 `--section-mode slide`。

跑完会打印每个文件「多少页 / 保留多少行 / 洗掉多少行噪声」，以及**跳过了多少行**，方便核对没把有用内容扔掉。原始文字想自己看，直接跑提取器：

```bash
python tools/ppt_extract.py "正课(1).ppt"                  # 按页打印
python tools/ppt_extract.py "正课(1).ppt" --txt 出来.txt    # 落成文本
python tools/ppt_extract.py "正课(1).ppt" --probe           # 体检：内部结构
```

### 电子书排版（.mobi）

正版电子书（Kindle 格式）是**目前最省事、最完整的一条路** —— 书里的 20 个 List、每个词条的音标和释义都现成，不用你手打，也不用去别处配释义。

它走的是**另一套工具**（`tools/mobi_extract.py` + `tools/mobi_words.py`），因为解析 MOBI 和解析课件完全是两回事：

| 工具 | 干什么 |
|---|---|
| `tools/mobi_extract.py` | 解开 MOBI 容器（PalmDB 记录表 + PalmDOC LZ77 解压），还原成 HTML/纯文本 |
| `tools/mobi_words.py` | 从正文里抽词表：**以「音标行」为锚**（`/ … /` 是全书最稳定的结构信号），往上定词头、往下收释义，并记住每个词属于哪个 List |

```bash
PY="C:/Users/ytc/.workbuddy/binaries/python/versions/3.13.12/python.exe"

# 一步到位：抽词表 → 发一份「核对稿」给你人工检查 → 直接导入 App
"$PY" tools/mobi_words.py "十天搞定考研词汇(乱序版).mobi" \
        --report "data/核对稿.txt" --out "data/词表.txt" \
        --name "十天搞定考研词汇（乱序版）" --per-day 2 --import

# 只看书的结构（目录、分节、词量），先摸底不抽词
"$PY" tools/mobi_words.py 书.mobi --stats

# 抽查若干词条的长相（音标有没有歪、释义有没有被截断）
"$PY" tools/mobi_words.py 书.mobi --review 20
```

`--report` 出的**核对稿**是给人看的：按 `Day N / LIST NN` 分组逐词列出（`序号.[+]单词  音标  释义`），末尾附**与书末索引的差异比对**和人工备注。`+` 号标记的是派生词条。抽完务必翻一遍——机器抽的，总要人过眼。

> **质量怎么量化？** 书末一般有个「索引」，那就是一份现成的权威词表。工具会拿抽出来的词跟索引逐条比，把「只在索引 / 只在抽取」的差集列在核对稿末尾。这些差集通常都解释得清（英式拼写 vs 美式拼写、只在词组里出现、索引自身漏收等）。

> **遇到疑似印刷错误怎么办？** 例：某处派生词条印成 `+office`，但音标 `/ˈɔːfisə/` 和释义都指向 `officer`。工具**原样保留、不擅自改**，只在核对稿备注里标出来，由你定夺。

### 关于那套「正课」PPT 的一个重要提醒

实测样本《十天搞定考研词汇·真题核心词汇精讲(1)》**不是词表，是讲义**：46 页里只有 5 个主讲词（intellect / transmit / diffuse / claim / forecast）加它们的派生词、词根词族，清洗后共 **43 个词条**。

也就是说这套课件是**真题核心词的串讲**，不是书上那 4600 个词的全量清单。它做补充词汇量很好（而且带音标带释义，质量高），但**不能用来替代完整词库**。想要全量，还是得走路径 A（内置十天计划）或路径 B（书的词序 + 开源词库配对）。

### List → Day 折叠

`--per-day N` 控制每 N 个 List 合成一天，**默认 2**（正是这本书的结构）：

- 分节是 `List 1` ~ `List 20` → 折成 10 天
- 分节本身已经是 `Day 1` ~ `Day 10` → **原样使用，不再折**（再折一次会把 10 天压成 5 天）
- 20 不能被 N 整除 → **不折叠**，宁可不折也不要错折

不想折叠加 `--per-day 1`。

### 支持哪些格式

| 扩展名 | 说明 |
|---|---|
| `.xlsx` | 每个 sheet 名自动成为一个分节；表头行自动跳过 |
| `.docx` | 段落与表格都读；`Day 1` 这类段落作为分节 |
| `.csv` `.tsv` | 逗号 / Tab 分隔。**释义里的全角逗号不会被吃掉** |
| `.txt` `.md` | 纯文本，结构化或书版排版都认 |
| `.json` | 支持 `[{word, phonetic, meaning}]`、`[{word, usphone, translation}]`、`[{word, translations:[{pos,translation}]}]` |
| `.ppt` `.pps` `.pot` | **旧版二进制课件**，按页提取 + 清洗。全程标准库，见上方「讲稿排版」 |
| `.pptx` `.ppsx` `.potx` | 新版课件（zip+XML），按页码排序提取 |
| `.mobi` | **Kindle 电子书**，直接抽词表（音标+释义+List 归属）。全程标准库，见下方「电子书排版」。`.azw` 是同族容器，大概率也能读但**未实测**；`.azw3`（KF8）正文结构不同，不保证 |
| `.pdf` | **不支持** —— 见下方说明 |

### PDF 怎么办

这台机器装不了 PDF 解析库（PyPI 不通），所以工具不接 PDF。而且 PDF 分两种，要看你是哪种：

- **带文字层的 PDF** → 用 Adobe / WPS / Word 打开，另存为 `.docx` 或 `.csv`，再走路径 C
- **扫描版 PDF（纯图片）** → 需要 OCR，不是导出格式能解决的；请从阅读器里**复制文字**粘贴到网页的「自定义词表」（路径 D）

正版电子书（得到 / 京东读书）带 DRM，导不出文字，这类只能走路径 B。

## 路径 D：网页端导入（不用重新部署）

适合 **txt / csv / tsv / json / md**，几千词以内。

1. 打开 Demo → 「词库」→ 拉到底部的 **「自定义词表」**
2. 点 **「选文件导入…」** 选文件，或把内容**粘贴**进文本框
3. 点 **「导入并开始」**

支持的每行写法（混用也行）：

```
abandon|/əˈbændən/|v. 放弃，抛弃          ← 竖线分隔，最明确
abandon,/əˈbændən/,v. 放弃                ← 逗号分隔（CSV）
abandon	/əˈbændən/	v. 放弃              ← Tab 分隔（从 Excel 直接复制就是这种）
abandon v. 放弃，抛弃                      ← 没音标也行
abandon                                    ← 只有单词也行（释义留空，回顾时自己回想）
```

分节标题单独写一行，这些写法都能识别：`# Day 1` / `## 第1天` / `[Day 1]` / `=== Day 1 ===` / `Day 1` / `第一单元`。

> **浏览器端不能解析 xlsx 和 docx**（二进制压缩包，网页里解不开）。这两种请走路径 C，或先在 Excel / Word 里另存为 CSV / TXT。

## 2. 常用参数

```bash
--name "显示名"        # 词库显示名，默认取第一个文件名
--out 路径             # 输出位置，默认 demo/wordlists.user.js
--per-day N            # 每 N 个 List 合并成一天（默认 2）
--no-fill              # 不从内置考研词库补音标 / 释义
--dump 路径            # 额外导出一份规范化 txt
--dir 目录             # 扫描整个目录里的词表（可多次），文件名按自然序排
--section-mode file|slide   # 讲稿分节：file=一文件一节（默认）/ slide=一页一节
--raw-deck             # 讲稿不做清洗，直接吃原始文字（调试用）
```

位置参数可以给多个文件，也可以直接给一个目录：

```bash
python tools/import_words.py a.pptx b.pptx        # 两个文件 → 两节
python tools/import_words.py "D:/ppt/正课"        # 整个目录 → 一节一个文件
```

多个文件时，**每个文件自动成为一个分节**，标签就是文件名（不含扩展名）。所以「正课1 ~ 正课10」十个课件导进来，App 首页就是整整齐齐的十天。

## 4. 分节为什么重要

这是「十天背完」这个需求的核心。App 的分组逻辑是：

1. **词表自带分节，且分节能完整覆盖全部词** → **按分节分组**，一组 = 一节
2. 没有分节 / 分节残缺 → **均分成 10 组**

所以只要词表带上 `Day 1` ~ `Day 10`（或 `List 1` ~ `List 20` 由工具折叠），App 就自动给你分成十天。如果解析出的分节和实际词数对不上（比如某天的标题漏了），App 会**退回均分十组**，而不是给出一个残缺的十天结构 —— 宁可退化成均分，也不给你一个错的分组。

## 5. 常见问题

**Q：导入后词库里还是旧的词？**
浏览器缓存。`Ctrl+F5` 强制刷新（手机上在设置里清站点数据）。

**Q：词库下拉里没看到新导入的？**
确认 `demo/wordlists.user.js` 也在服务器上 —— 导入的词库都在这个文件里。`tools/pack.py` 会自动带上，手动上传时别漏。

**Q：xlsx 只解析出几个词？**
八成是数据不在第一个 sheet，或表格前面有很多合并单元格的标题行。加 `--dump` 导出一份规范化文本看看解析结果。

**Q：书版排版解析出来一堆乱七八糟的词？**
加 `--dump` 看规范化结果，把可疑的行贴给我，我按你的实际排版调规则。这类排版变体很多，规则是照着真实文件迭代出来的。

**Q：ppt 导进来只有几十个词，是不是解析坏了？**
先确认课件本身有多少词。那套「正课」是**真题核心词精讲**，一个文件就 5 个主讲词带一窝派生词，43 个词条是正常结果 —— 见上方「关于那套正课 PPT 的提醒」。

**Q：ppt 里明明有的词没提出来的？**
先用提取器看原始文字，确认它在不在文字记录里：
```bash
python tools/ppt_extract.py "正课(1).ppt" --txt raw.txt     # 清洗后的行
python tools/ppt_extract.py "正课(1).ppt" --raw --txt 原始.txt  # 未清洗的行
```
- 两处都没有 → 那个词是**图片**（截图/艺术字），不是文字，解析不了
- 只有 `--raw` 里有 → 被清洗规则误伤了，把那一行贴给我，我加例外

**Q：.ppt 会不会被当成 .pptx？**
不会。工具看文件头：OLE2（`D0CF11E0`）走二进制解析，zip（`PK`）走 XML 解析。文件名叫 `.ppt` 实际是 pptx（WPS 另存时常见）也能正确处理。

**Q：能不能直接扒网上的 txt 版本？**
不做这个。见第 0 节 —— 书的释义和例句是受保护内容，而且静态站点挂在公网上等于向公众分发。单词顺序 + 开源词库配释义（路径 B）能达到一样的效果。

**Q：墨墨 / 扇贝的词库能用吗？**
墨墨的开放 API 拿不到释义（`/vocabulary` 只返回 id 和拼写），不能当词库用；扇贝没有公开接口。用开源词库或自己的电子资源更靠谱。
